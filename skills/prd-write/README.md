# PRD Write

把产品意图写成可评审、可交接、可持续维护的需求文档。它只记录本次功能的决策，不重复抄写已确认的全局产品规则，也不写逐像素的 UI 实现说明。

## 何时使用

- 首版产品或重大新模块，需要重新对齐问题、用户、策略和指标（**完整模式**）。
- 已在迭代的产品新增或调整一个功能，写清本次变化及其与体验基线的关系（**增量模式**，默认）。
- 需要修订一份已有 PRD，而不是从零起草。

## 输入

- 用户提供的需求、研究、数据、竞品、截图和工程限制。
- 上游 `requirement-clarify` 产出的 `clarify.md`（如已跑过）。
- `docs/product/<project-name>/` 下的产品体验基线（如已建立）。
- 相关现有 PRD、受影响页面和相关代码。

## 产物

```text
docs/prd/<feature-name>/
├── prd.md              # 本 Skill 的产物
├── design.md           # 可选：设计规格
├── prototype.html      # 可选：独立评审原型
└── demo.md             # 可选：项目内演示结论
```

以 [template.md](template.md) 为骨架。增量模式必须保留 0、1、2、5、7、8、9、10 节；3、4、6 节可精简为“沿用现有结论”或省略。

## 不做什么

- 不把 PRD 写成全产品说明书——增量功能只写变化，其余链接到体验基线。
- 不把设计细节当需求——视觉细节交给 `design.md` 或原型。
- 不虚构产品级规则——没有基线时标记“无体验基线”，而不是自己编一套。
- 小型 bug、文案修正或已完全明确的工程任务不需要完整 PRD。
