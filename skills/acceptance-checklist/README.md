# 验收清单

基于 PRD 和交付包，生成一份研发提测后、上线前能逐条走查的产品验收清单。

它的关键不在「列了多少条」，而在**每条都指回 PRD 的需求编号**——没通过时能立刻分清是需求没写清，还是实现没做到。

## 何时使用

- 研发提测后的产品走查（Sanity Check）。
- 上线前的功能验收。
- 视觉与交互还原度核对。

## 不适用

- 写测试代码或跑自动化测试 → 那是测试的活。
- 审查代码质量、判定版本能否发布。
- 需求还没定 → 回到 `prd-write`。

本 Skill 产出的是**产品验收**清单，不是测试用例：测试用例覆盖实现分支，验收清单覆盖**用户可感知的结果**。

## 输入

- `prd.md`（**必需**——没有就先用 `prd-write` 写）。
- `prototype.html`、`demo.md`（有则读）。

## 产物

```text
docs/prd/<feature-name>/
└── acceptance.md       # 四个维度 × P0/P1/P2，每条含预期结果与依据出处
```

四个维度：**核心流程**（P0）、**边界与异常**（P0/P1）、**UI 还原度**（P1/P2）、**数据埋点**（P2）。

需要浏览器里点着走查、看通过率进度时，让 AI 依据 `acceptance.md` 生成一份单文件 HTML 即可——本 Skill 不预置也不依赖任何前端框架或本地服务。

## 不做什么

- 不写测试代码，不替代测试。
- 不执行测试，也不判定版本能否发布。
- 不凭原型反推需求并当成验收依据。
- 不引入外部框架或需要常驻进程的本地服务。

## 下一步

走查完成后按归属人整理未通过项；若暴露出需求本身的缺口，回到 `grill-with-prd` 或用 `prd-write` 补齐。
