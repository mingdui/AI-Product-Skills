# Design Spec Prototyper

把 `design.md` 和产品需求变成独立、可点击、可评审的高保真原型。它的视觉事实来源是设计规格，不是临时发挥。

## 何时使用

- PRD 和设计依据已经明确，需要先评审体验。
- 需要一个不依赖真实后端的 `prototype.html`。
- 需要展示页面状态、响应式布局、表单和关键交互。

## 输入

两类输入**同时参考**：

- **`design.md` / `DESIGN.md`** —— 品牌令牌、组件规则、字体。它是**持续沉淀的产品事实**，
  不只是本次的中间产物。
- **设计稿图片或截图** —— 本次页面的实际构图：分区、元素顺序、层级、间距节奏。

另外还会读：相关 `prd.md` 和产品体验基线（如存在），以及你指定的技术栈、字体和交互范围。

**两者冲突时**：令牌类（颜色、字体、圆角、间距基准）**以规格为准**——规格是沉淀下来的产品事实；
构图类（分区、元素顺序、层级）**以图片为准**——那正是这次要还原的东西。冲突会在交付说明里点出来。

## 产物

```text
docs/prd/<feature-name>/
├── prd.md
├── design.md
├── prototype.html
└── assets/fonts/        # 使用本地字体时才创建
```

在线独立原型默认可使用 Google Fonts；需要离线或稳定复现时，使用授权的本地字体或系统字体 fallback。

## 不做什么

- 不把独立 HTML 当作正式生产架构。
- 不凭截图猜测隐藏业务规则、API 或权限。
- 不覆盖已有需求目录中的原型文件。
