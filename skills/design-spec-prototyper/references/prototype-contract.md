# 原型契约

## 需求资产目录

- 默认交付文件为 `docs/prd/<feature-name>/prototype.html`，并与该功能的 `prd.md`、`design.md` 等资产保持在同一目录。
- 先从 PRD 或设计规格路径推断 `<feature-name>`；无法确认时先询问，不得输出到通用 `outputs/` 目录。
- 若功能目录已存在，复用它；不得为同一需求创建多个相似文件夹，也不得覆盖已有原型。

## 字体来源与排版

- 在实现前记录 `font_source: google | local | system`、字体族、实际字重/样式、中文 fallback 和离线要求。
- 在线独立原型默认 `google`：用户或设计规格可直接指定 Google Fonts 的字体族；仅引入实际使用的字重和样式，使用 CSS2 链接、`preconnect`、`display=swap` 和系统 fallback。
- `local` 字体置于 `assets/fonts/` 并通过相对 `@font-face` 引用；只使用用户提供或确认可用的字体文件。
- 用户提供的字体文件直接用，来源由用户判断。用户没提供时：从截图能看出的字体名标 `[INFERRED]` 或 `[UNKNOWN]`，并使用最接近的 fallback——不要自己去网上找字体文件。
- 预览检查必须覆盖字体加载失败后的换行、截断、溢出和控件尺寸；不得将文字转成 SVG 或图片。

## 阅读设计规格

实现前提取以下字段：

- 当前端的产品体验基线、可复用原型页壳和已确认页面模式；没有时明确记录缺口。
- 页面目的、主要操作与目标用户。
- 令牌：画布、表面、文本层级、强调色、边框、间距、圆角、阴影、动效和排版。
- 桌面端层级、可见组件变体和内容顺序。
- 响应式证据与明确未知项。
- 无障碍要求，包括焦点、语义化标签和非颜色状态提示。

产品体验基线与功能设计规格冲突时，除非用户已明确批准偏离，否则保留基线。标为已观察的值必须作为复刻约束。标为推断的值是默认选择，只有实现约束要求时才能调整。不得虚构没有证据支持的产品行为。

## 原型质量标准

- 添加装饰效果前，先保留已记录的视觉层级。
- 使用可复用令牌，避免在每个组件重复硬编码数值。
- 主要操作在视觉上必须突出，并遵循记录的品牌处理方式。
- 表单应足以展示正常交互：标签、必填状态、有用的自动填充值、适用时的密码可见性，以及可见焦点。
- 为非必要动画使用 `prefers-reduced-motion`。
- 实现文本溢出、窄屏换行和适合触控的控件尺寸。

## 独立 HTML 检查

- 包含 `<!doctype html>`、语言、视口、标题和简洁描述。
- 保持 ID 唯一，并为每个可见表单控件关联标签。
- 纯图标按钮须有 `aria-label`；装饰性 SVG 须标记 `aria-hidden="true"`。
- 操作使用按钮，导航使用链接。
- 演示原型默认不接真实支付、不提交凭据、不调用外部服务——**这些默认值是为了让评审不产生副作用，
  不是因为本 Skill 要管合规**。用户明确要求接真实链路时照做，做之前把风险说清楚（会产生真实扣款 /
  会外发数据 / 测试完要清理）。
- `google` 字体是网络依赖；用户要求离线、网络不可控或版式必须稳定时，改用 `local` 或 `system`。

## 交付格式

说明：

1. 功能资产目录、输出路径与目标技术栈。
2. 使用的设计规格证据，包括关键令牌和组件规则。
3. 使用的产品体验基线章节，以及有意偏离或候选晋升模式。
4. 仅列出确实增加价值的补充设计指导（若调用过设计类 skill，说明用了哪一条）。
5. 已执行的检查和预览限制。
6. 需要真实设计参考或产品决策才能确定的未知或推断选择。
7. 字体来源、使用的字体族/字重、fallback，以及字体加载验证结果。
   **品牌字体拿不到时，必须声明替代关系**：替代了谁、哪个字形维度不同（比如「`sohne-var`
   是几何无衬线，这里用系统 `-apple-system` 栈替代，字宽偏窄、字重阶梯少一档」）。
   只写「换成了自有字体」等于没说——下一次迭代还得重新判断一次。
8. **构图来源**：本次的分区顺序是从哪来的——设计稿 / `prd.md` 第 5 节 / 设计规格 / 参考图。
   参考图不属于本页时，明确写「构图以 PRD 为准，参考图只用于视觉语言」。
9. 若本次读到「无产品基线」，提一句：这类页面如果还会再做，值得跑一次
   `product-experience-foundation`。**只说一次，不要每步都提醒。**
