# Web Design Extractor

把网页或截图中的可见设计证据整理成可实施的 `design.md`。它记录“看到了什么”和“哪些只是推断”，不负责猜隐藏业务逻辑。

## 何时使用

- 有品牌网站、竞品链接或页面截图。
- 需要复刻视觉风格、布局、组件或响应式行为。
- 需要为原型或开发提供一份可引用的设计规格。

## 输入

- 公开或用户授权的 URL。
- 一张或多张网页截图。
- 可选的目标视口和要关注的页面状态。

## 怎么拿证据

**有浏览器和没浏览器，拿到的不是一回事。**

| 路线 | 要什么 | 拿到 | 证据等级 |
| --- | --- | --- | --- |
| **浏览器（优先）** | 项目里有 playwright，或机器上有 Chrome / Edge | **计算样式**、四档视口实测、截图 | `[OBSERVED]`，可以直接当复刻约束 |
| **源码（退路）** | 只要能发 HTTP 请求 | 服务端返回的 HTML、声明的 CSS 变量 | 只能算 `[INFERRED]` |

差别不是理论上的。实测同一个页面：

- 源码里写着「导航高 `64px`」，浏览器量出来是 **76px**
- 源码里看不到标题字重，实测是 **500**（`700` 全页只用了 9 次）
- 源码里看不到正文色，实测是 **`#425466`**（用了 1716 次）

**颜色类两条路线基本一致；尺寸、形态、字重类，源码路线基本是错的。**
因为颜色令牌通常一跳到位，尺寸要走层叠和媒体查询——变量声明只是「定义了什么」。

两条路线是**叠加**关系，不是二选一：源码给「定义了哪些令牌、叫什么名字」，
浏览器给「哪些真的在用」。能同时走就走两条。

细节、坑和脚本用法见 [references/browser-route.md](references/browser-route.md)。

## 产物

- 用户指定目录下的 `design.md`。
- 在本项目中，推荐放入 `docs/prd/<feature-name>/design.md`。
- 规格会使用 `[OBSERVED]`、`[INFERRED]`、`[UNKNOWN]` 区分证据等级。

## 不做什么

- **不替你做合规判断。** 登录后、私有或付费墙后的内容要不要分析，由你决定——你要求做就做。
- 不声称获得了网站源码、隐藏 CSS、接口或未展示的交互。
- 不把截图中的推断写成已确认的产品规则。

## 下一步

将确认后的 `design.md` 交给 `$design-spec-prototyper` 生成独立评审原型；如果只需要外部视觉证据，也可以先由产品经理评审规格。

详细规则见 [SKILL.md](SKILL.md)。
