# 适配契约

## 交付前门禁

在适配任何生产代码前，先确定交付路径：

- 用户或项目规则明确要求 OpenSpec、Superpowers 或其他工程治理流程时，遵循该流程并创建 / 更新其工件；不要直接实现业务代码。
- `auto` 模式下，检查 `AGENTS.md`、贡献指南、项目目录和配置；涉及接口、数据、权限、迁移、跨模块或高风险发布的变更，优先进入已配置的工程治理流程。
- 仅当项目未要求治理流程且变更局部、低风险、可由现有架构直接覆盖时，才执行直接适配。
- 工具不存在、模板不明或路径有歧义时，不得伪造 OpenSpec、Superpowers 或等价工件；记录缺口并请求确认。

所有路径都以功能 `prd.md`、`design.md`、确认的 `prototype.html`、`demo.md`（如有）和产品体验基线为共同输入。工程工件引用这些来源，不复制成第二套产品事实。

当项目没有等价工件时，功能目录的 `delivery.md` 至少记录：

```text
delivery_mode: direct | openspec | superpowers | <project-workflow>
decision: 选择原因、仓库证据与风险等级
inputs: prd.md, design.md, prototype.html, demo.md, 产品体验基线
handoff: 直接实现范围，或待创建 / 更新的工程治理工件
```

## 保留

- 已批准原型的信息层级、内容顺序、组件结构和主要操作。
- 当前端已确认的产品体验基线：产品术语、信息架构、页面模式和共享交互规则。
- 设计规格令牌和由证据支撑的视觉要求。
- 现有仓库关于路由、状态、组件、样式、图标、数据访问和测试的约定。
- 无障碍契约：语义结构、标签、焦点、键盘行为、对比度、非颜色状态提示与减少动态效果支持。

## 替换

- 原型专用 CDN、重置样式、模拟处理器、内联模拟数据、外部图标 URL 和本地伪路由。
- 不属于当前项目的框架专用标记。
- 当项目已有等价物时，替换重复的按钮、输入框、卡片、导航和令牌定义。
- 不受支持的交互和集成：改用本地且明确的占位符，或仓库的标准不可用状态。

## 创建前检查

先寻找最接近的现有实现：

- 相同页面类型的路由。
- 现有表单、按钮、对话框、卡片、页面外壳和响应式布局组件。
- 主题和令牌定义。
- 已使用的无障碍图标基础组件与图标。
- 相关路由、组件或交互的测试。
- 产品体验基线中已确认的同类页面模式与组件规则。

只有检查确认现有基础组件无法干净地表达需求后，才能创建新代码。

## 生产就绪检查表

- 没有现有集成或用户明确授权时，原型表单不得提交到真实端点。
- 不得硬编码密钥、用户数据、认证令牌或特定环境 URL。
- 不得仅为还原微小视觉细节添加依赖；优先使用本地基础组件和原生平台能力。
- 错误、加载、空态、禁用和长内容行为必须与相邻产品页面保持一致。
- 截图是视觉证据，不是隐藏 API、状态或交互的证明。
- 只在模式已被产品基线确认可复用时新增共享组件；首次或一次性模式保持功能局部，并在交付中记录候选晋升建议。

## 验证矩阵

| 范围 | 验证内容 |
| --- | --- |
| 架构 | 路由注册、导入、数据/状态归属、项目组件复用 |
| 视觉 | 令牌、桌面端层级、在本地断点无回归 |
| 响应式 | 窄屏布局、无水平溢出、触控目标、内容换行 |
| 无障碍 | 标签、地标、焦点顺序、键盘使用、状态提示、减少动态效果 |
| 质量 | 相关代码检查/类型检查/测试/构建，以及无无关改动 |
