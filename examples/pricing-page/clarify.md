# 需求澄清：SaaS 定价页

> 功能名：`pricing-page`
> 输入需求原话：「我们不做自助下单，客户最终都要走销售。但没有公开定价页，销售每次都要从头解释价格。做一个页面把定价摆清楚，让客户自己先看懂，愿意聊的再留资。参考 Stripe 那种，月底上线。」
> 产出用途：作为 `prd-write` 的输入。本文件不含 PRD 正文。

## 2. 目标角色与权限差异

**转化形态：纯销售导向**

| 角色 | 说明 |
| --- | --- |
| **团队负责人 / 部门主管（主角色）** | 5–50 人团队中实际决定购买的人。关心「好不好用、值不值这个价」，不关心采购流程或招标 |
| **销售** | 页面产生的全部线索的唯一去向 |
| 未登录访客 | 可访问、可比较，但**无任何自助购买或自助注册入口** |

**权限差异**：本期不涉及登录态差异。产品内已登录用户的升级 / 降级路径不在本次范围。

**公开价格的作用**
四档价格公开，但**不承担成交职能**——作用是筛选线索质量、锚定预算区间，不是促下单。这一点必须在 PRD 里写明，否则下游会照 Stripe 的自助逻辑去设计 CTA。

**未确认项**
- 销售线索去向（表单收件人、是否写入 CRM、是否用预约链接）：`[UNKNOWN]`，归属人待定
- 是否需要按行业 / 规模给不同档位视图：`[UNKNOWN]`，归属人待定

## 4. 范围

### 4.1 计价模式

**固定一口价 × 3 档，不按席位、不按用量。**

- 每档一口价，不随人数变化，全公司统一
- 不区分席位，价格卡不需要席位选择器
- 人数由**档位上限**控制，而非按人加价

### 4.2 本期包含的模块

| # | 模块 | 本期形态 |
| --- | --- | --- |
| 1 | 价格卡 + 月付/年付切换 | 三张有价卡 + 企业版区块；月/年切换显示年付总价、折算月价、省幅 |
| 2 | 核心权益清单 | 每档 5–8 条核心权益。**不做**逐项打勾的功能对比大表 |
| 3 | 计费规则说明 | 一段文字说明。**不做**用量估算器或交互式计算工具 |
| 4 | FAQ + 企业版联系区块 | FAQ 覆盖费用、安全、人数上限、方案变更、联系方式；企业版区块引导留资 |

### 4.3 页面终点：留资

- 全页唯一的转化动作：提交「预约演示」/「联系销售」表单
- 无试用链路，也不提供自助注册
- 定价页不碰支付、不碰开通、不碰试用
